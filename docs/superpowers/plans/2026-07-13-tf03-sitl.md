# Benewake TF03 in SITL — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SITL's simulated altimeter behave like the Benewake TF03 the airframe actually carries (0.1–180 m, landing-only), instead of a generic 327.67 m rangefinder that ArduPlane never reads.

**Architecture:** Three independent changes. (1) `config/sitl-extra.parm` gets the TF03's real limits plus `RNGFND_LANDING 1` — the one line that changes behaviour. (2) `sitl.sh` grows a single `warn_eeprom_overrides()` that fires when a stored eeprom could silently defeat those defaults, replacing the terrain-only warning it has today. (3) `SITL-CHEATSHEET.md` loses its now-false "327.67 m ceiling" paragraph.

**Tech Stack:** Bash, ArduPilot parameter files, pymavlink 2.4.49 (already installed) for reading live params.

Spec: `docs/superpowers/specs/2026-07-12-tf03-sitl-design.md`

## Global Constraints

- **A `.parm` name that doesn't exist in this firmware is a boot panic**, not a warning (`AP_Param::load_defaults_file`). All five names used here were verified present in 4.5.7.
- **A stored `sitl-run/eeprom.bin` value beats any `--defaults` line.** There is no CLI override. Every verification must read the **live** value over MAVLink, never the `.parm` file.
- **Build interpreter is `python3.10`** — waf deadlocks under 3.12. `sitl.sh` already handles this.
- **Never pipe waf** — a piped exit status belongs to the pipe, so a failed build reports success.
- **Commit style on this branch:** `SITL: <lowercase imperative>` (see `git log`).
- **Do not commit `SITL-CHEATSHEET.pdf`** — it is gitignored as a derived artifact.

- [ ] **Step 1: Write the verification script**

This reads the **live** parameter over MAVLink — the layer that acts. Reading the `.parm` file back would prove nothing.

Create `check_params.py` in the scratchpad directory:

```python
#!/usr/bin/env python3
"""Read live SITL params over MAVLink. The .parm file is not the acting layer."""
import sys, time
from pymavlink import mavutil

WANT = ["RNGFND_LANDING", "RNGFND1_MAX_CM", "RNGFND1_MIN_CM"]

m = mavutil.mavlink_connection("tcp:127.0.0.1:5760")
if not m.wait_heartbeat(timeout=60):
    sys.exit("no heartbeat from SITL")

got, deadline = {}, time.time() + 30
last_req = 0.0
while time.time() < deadline and len(got) < len(WANT):
    if time.time() - last_req > 3:          # re-request; PARAM_VALUE can be dropped
        for name in WANT:
            if name not in got:
                m.mav.param_request_read_send(
                    m.target_system, m.target_component, name.encode(), -1)
        last_req = time.time()
    msg = m.recv_match(type="PARAM_VALUE", blocking=True, timeout=1)
    if msg and msg.param_id in WANT:
        got[msg.param_id] = msg.param_value

for name in WANT:
    print(f"{name} = {got.get(name, 'MISSING')}")
sys.exit(0 if len(got) == len(WANT) else "timed out waiting for params")
```

- [ ] **Step 3: Rewrite the rangefinder block**

In `config/sitl-extra.parm`, replace the whole block from `# Simulated downward rangefinder,` through `RNGFND1_MAX_CM 32767` with:

```
# The simulated downward altimeter, modelled on the Benewake TF03 this airframe
# actually carries: 0.1-180 m, 0.5 deg beam, used for landing only.
#
# Type 100 is the SITL backend (AP_RangeFinder.h Type::SIM); it publishes SITL's
# height_agl. That height is terrain-aware ONLY when TERRAIN_ENABLE=1 and a tile
# covers the vehicle. Otherwise set_height_agl() (AP_HAL_SITL/SITL_State.cpp)
# silently falls back to a flat-earth model and reports height above HOME.
# Nothing warns you: the sensor still tracks your climbs and descents, it just
# never sees a hill. ./sitl.sh --terrain checks for the tile up front.
RNGFND1_TYPE 100
RNGFND1_ORIENT 25

# TF03 range, as AP_Int16 centimetres (these become metre floats in 4.6's
# RNGFND1_MIN/MAX). Past MAX the frontend reports OutOfRangeHigh and Plane falls
# back to the baro -- it does not clamp the value (AP_RangeFinder_Backend.cpp,
# update_status).
RNGFND1_MIN_CM 10
# 18000 is not merely a cutoff. rangefinder_height_update() (ArduPlane/altitude.cpp)
# scales its in-range latch off MAX: it wants 10 samples differing from the first
# by >5% of MAX, and resets the count on a jump >20% of MAX. At the old 32767 those
# gates were 16.4 m and 65.5 m; at the real 180 m they are 9 m and 36 m. Padding MAX
# does not just admit impossible readings, it desensitises the landing latch.
RNGFND1_MAX_CM 18000

# Without this the TF03 has no effect on flight at all. rangefinder_height_update()
# still polls the sensor every cycle, but rangefinder_correction() gates USE of the
# reading on (RNGFND_LANDING && flight_stage == LAND), so at the firmware default of 0
# every consumer ignores it. Landing is also the only thing ArduPlane ever uses a
# rangefinder for, so "landing only" needs no further restricting.
#
# A stored eeprom.bin value beats this default -- ./sitl.sh says so, --wipe fixes it.
RNGFND_LANDING 1

# Deliberately NOT set: SIM_SONAR_RND, the sensor noise amplitude (default 0). The
# TF03's real error -- +/-10 cm close in, ~1% (1.8 m) at 180 m -- is dwarfed by the
# ~6% baro bias in SITL-CHEATSHEET.md, and a deterministic sim is worth more than
# cosmetic jitter.
#
# SIM_SONAR_GLITCH cannot help here either -- but NOT because it does nothing. It is
# read (AP_HAL_SITL/sitl_rangefinder.cpp, _sonar_pin_voltage) by the ANALOG rangefinder
# path, where it forces a max-distance reading with the given probability. RNGFND1_TYPE
# 100 never goes through that path: Type::SIM reads rangefinder_m[] straight from
# Aircraft::rangefinder_range(), which consults sonar_noise and not sonar_glitch. So
# setting it has no effect on THIS config, and glitching would have to be written.
```

- [ ] **Step 2: Add the function**

In `sitl.sh`, immediately after the `die()` definition (line 28), insert:

```bash
# --defaults sets DEFAULTS, and a value already stored in the EEPROM beats a
# default: AP_Param only takes a default for a parameter it has never seen. So any
# eeprom.bin left by an earlier session -- or one stray write from QGC -- makes a
# line in config/*.parm a silent no-op. There is no command line option to force a
# value (SITL's -P sets a default too), so say it out loud instead of pretending.
warn_eeprom_overrides() {
  [[ -f "$RUN_DIR/eeprom.bin" ]] && (( ! WIPE )) || return 0

  log "eeprom   NOTE: $RUN_DIR/eeprom.bin exists and a stored parameter beats a"
  log "eeprom         default, so a line in config/*.parm can be a silent no-op."
  log "eeprom         Confirm these in QGC after boot; if one is wrong, --wipe:"
  log "eeprom           RNGFND_LANDING 1 -- at 0 the TF03 is simulated and then"
  log "eeprom                              ignored: ArduPlane only ever reads a"
  log "eeprom                              rangefinder for landing, and only when"
  log "eeprom                              this is 1."
  if (( TERRAIN )); then
    log "eeprom           TERRAIN_ENABLE 1 -- at 0 --terrain did nothing: home is"
    log "eeprom                              still anchored on the terrain, so the"
    log "eeprom                              launch looks right while height_agl"
    log "eeprom                              quietly stays flat-earth."
  fi
}
```

- [ ] **Step 3: Delete the old terrain-only warning**

In the `if (( TERRAIN ))` block, delete this entire passage (lines 108-118) — its content now lives in the function above, and leaving it would double-print on a `--terrain` run with a stale eeprom:

```bash
  # --defaults sets DEFAULTS, and a value already stored in the EEPROM beats a
  # default. So a saved TERRAIN_ENABLE=0 -- one stray write from QGC -- makes
  # --terrain a silent no-op: home still gets anchored on the terrain below, so
  # the launch looks right, while height_agl quietly stays flat-earth. There is
  # no command line option to force a value (SITL's -P sets a default too), so
  # say it out loud instead of pretending.
  if [[ -f "$RUN_DIR/eeprom.bin" ]] && (( ! WIPE )); then
    log "terrain  NOTE: $RUN_DIR/eeprom.bin exists, and a stored parameter overrides"
    log "terrain        the defaults below. If QGC shows TERRAIN_ENABLE 0 after boot,"
    log "terrain        --terrain did nothing: rerun with --wipe, or set it in QGC."
  fi
```

Leave `DEFAULTS="$DEFAULTS,$TERRAIN_PARM"` and the `spacing=` lookup that surround it untouched.

landing latch.

## Definition of done

- `./sitl.sh --wipe` boots and the live params read `RNGFND_LANDING=1`, `RNGFND1_MAX_CM=18000`, `RNGFND1_MIN_CM=10` over MAVLink — not merely in the file.

- No SITL processes left running.

## Deliberately out of scope

Carried from the spec — do not implement these:

- **Sensor noise** (`SIM_SONAR_RND` stays 0) and **glitching** (`SIM_SONAR_GLITCH` is read only by the *analog* rangefinder path, `_sonar_pin_voltage()`, which `RNGFND1_TYPE 100` never takes — so it has no effect on this config).
- **Simulating the TF03 serial device** (`sim:benewake_tf03`, driver type 27). Rejected: `SIM_SerialRangeFinder` encodes `uint16` cm with no clamp, so above 655.35 m AGL its reading wraps (700 m → a valid-looking 44.6 m).
- **`RNGFND1_GNDCLEAR`** stays at its 10 cm default — it needs the TF03's real mounting height *and* a matching `SIM_SONAR_POS`, as a pair. Ask before setting either.
- **A flown auto-landing.** Nothing here proves `rangefinder_state.in_use` latches during LAND, or measures the real size of the correction step. It remains the open question, and it is now answerable.
