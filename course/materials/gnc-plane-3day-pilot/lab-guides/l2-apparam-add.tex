\section*{Lab summary for the instructor}

\textbf{Learning objective:} The engineer can add a typed parameter to a live ArduPilot vehicle class, annotate it correctly with \texttt{@Param}, add an \texttt{AP\_GROUPINFO} entry at a unique index, rebuild, and observe the parameter through the MAVLink \texttt{PARAM\_VALUE} stream. Secondary objective: confirm NVM persistence via the EEPROM re-read on restart.

\textbf{Depth:} internals --- engineers are reading \codepath{ArduPlane/Parameters.cpp} and \texttt{AP\_PARAM\_FLAG\_*} defines, not just clicking in a GCS.

\textbf{Feed-forward:} \texttt{AP\_GROUPINFO} is the universal parameter registration mechanism across all ArduPilot subsystems. Every subsequent lab modifies or observes parameters from this same table. Understanding the index-is-baked-in constraint here prevents confusion when engineers look at real subsystems in M5's code walk.

\section*{Pointers to advanced material}

\instadvanced{When an engineer asks ``what happens if two subsystems accidentally use the same index?'': the compile-time check is a static assert in \citefile{libraries/AP\_Param/AP\_Param.cpp} that catches duplicates within the same group. But mismatched indices across restarts --- a firmware upgrade that inserts a parameter at an existing index --- silently writes the wrong value. This is the ``indices are baked into user configs'' constraint; it matters when migrating a production fleet. M10 returns to this when the engineers extract \texttt{AP\_TECS} and see how to isolate the parameter table from the vehicle binary.}

\section*{What you will do}

In this lab you will modify two ArduPlane source files to add a brand-new parameter (\texttt{MY\_PARAM}) to the \texttt{ParametersG2} struct, rebuild SITL, and watch the parameter show up live in the running sim at its default value of 17.0. You will then change it to 42.0 and restart SITL to confirm the value survives the restart --- demonstrating ArduPilot's NVM persistence mechanism.

This is the fastest way to understand why \texttt{AP\_GROUPINFO} index numbers matter and how the parameter table drives both MAVLink exposure and EEPROM storage. Every subsystem you look at in later modules uses this exact pattern.

\section*{Before you start}

\begin{itemize}
  \item Working SITL binary from Module M3. A standard (non-debug) build is fine: \texttt{./waf configure --board sitl \&\& ./waf plane}.
  \item \texttt{pymavlink} installed: \texttt{pip3 install pymavlink}.
  \item Both \codepath{ArduPlane/Parameters.h} and \codepath{ArduPlane/Parameters.cpp} in their unmodified state (\texttt{git status} shows no changes).
  \item One terminal in the repository root.
\end{itemize}

\section*{The steps}

\subsection*{Step 1 --- Apply the source patch}
\begin{Verbatim}[frame=single,fontsize=\small]
git apply course/labs/gnc-plane-3day-pilot-l2-apparam-add/patch/l2-my-param.patch
\end{Verbatim}
This adds \texttt{AP\_Float my\_param;} to \texttt{ParametersG2} in \codepath{Parameters.h} and one \texttt{AP\_GROUPINFO("MY\_PARAM", 42, ...)} entry in \codepath{Parameters.cpp}.

You can also apply the changes by hand --- open the patch file and follow the \texttt{+} lines.

\subsection*{Step 2 --- Rebuild}
\begin{Verbatim}[frame=single,fontsize=\small]
./waf plane
\end{Verbatim}
Typically 10--20 s (incremental). Confirm \texttt{[2/2]} or similar; no compilation errors.

\subsection*{Step 3 --- Start SITL}
\begin{Verbatim}[frame=single,fontsize=\small]
Tools/autotest/sim_vehicle.py -v ArduPlane -f plane --console --no-rebuild
\end{Verbatim}

\subsection*{Step 4 --- Show MY\_PARAM at its default}
\begin{Verbatim}[frame=single,fontsize=\small]
param show MY_*
\end{Verbatim}
Expect: \texttt{MY\_PARAM 17.000000}.

\subsection*{Step 5 --- Change MY\_PARAM}
\begin{Verbatim}[frame=single,fontsize=\small]
param set MY_PARAM 42.0
\end{Verbatim}
Expect: \texttt{Set MY\_PARAM to 42.000000}.

\subsection*{Step 6 --- Quit SITL}
In MAVProxy: \texttt{quit} or \texttt{Ctrl-C}.

\subsection*{Step 7 --- Restart SITL (same directory)}
\begin{Verbatim}[frame=single,fontsize=\small]
Tools/autotest/sim_vehicle.py -v ArduPlane -f plane --console --no-rebuild
\end{Verbatim}

\subsection*{Step 8 --- Verify persistence}
\begin{Verbatim}[frame=single,fontsize=\small]
param show MY_*
\end{Verbatim}
Expect: \texttt{MY\_PARAM 42.000000}.

\subsection*{Step 9 --- Restore default and clean up}
\begin{Verbatim}[frame=single,fontsize=\small]
param set MY_PARAM 17.0
\end{Verbatim}
Quit SITL. Then:
\begin{Verbatim}[frame=single,fontsize=\small]
git checkout ArduPlane/Parameters.h ArduPlane/Parameters.cpp
\end{Verbatim}

\section*{What success looks like}
\begin{itemize}
  \item After Step 4: \texttt{MY\_PARAM 17.000000} in MAVProxy.
  \item After Steps 5--8: \texttt{MY\_PARAM 42.000000} in MAVProxy on the new session.
\end{itemize}

If \texttt{MY\_PARAM} is not in the list, the binary was not rebuilt after patching. Stop SITL, run \texttt{./waf plane}, retry.

If after restart you still see \texttt{17.0}, EEPROM was not written (or was cleared). Most common cause: SITL was launched from a different working directory on the second launch.

\section*{Common mistakes and quick fixes}

\begin{enumerate}
  \item \textbf{MY\_PARAM not visible at all} --- you forgot \texttt{./waf plane}. Rebuild and re-launch.
  \item \textbf{Compilation error: index 42 already used} --- two \texttt{AP\_GROUPINFO} entries share index 42. Open \codepath{Parameters.cpp}, search for \texttt{42,} in \texttt{ParametersG2::var\_info}, assign a different unused index.
  \item \textbf{MY\_PARAM reverts to 17.0 after restart} --- SITL launched from a different directory; the EEPROM file is a different file. Launch both from the repo root with \texttt{--no-rebuild}.
  \item \textbf{\texttt{param show MY\_*} returns nothing, even after rebuild} --- patch may have a typo. Check the line reads exactly \texttt{AP\_GROUPINFO("MY\_PARAM", 42, ParametersG2, my\_param, 17.0f)} and that \texttt{my\_param} is declared in the class body in \codepath{Parameters.h}.
  \item \textbf{\texttt{git apply} fails with ``already applied''} --- the patch was applied before. \texttt{git status}; if files are already modified, skip Step 1.
\end{enumerate}
